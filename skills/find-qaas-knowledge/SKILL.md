# Find QaaS Knowledge (docs-or-silence router)

Resolve any "where is X / which doc covers Y" question to a concrete source. Never
answer QaaS specifics from memory.

## Resolution order

1. **QaaS graph (discovery for cross-repo code and dependencies).** Apply
   `qaas-graph-workflow` to locate an existing checkout or clone `qaas-graph`
   only when needed. Query committed artifacts before rebuilding:
   - `graphs/repositories.json` for evaluated project/package dependency facts
     and their recorded source commits.
   - `graphify-out/graph.json` via `graphify query`, `explain`, or `path` for
     code-level ownership, symbols, and relationships.
   Treat the graph as a derived index: record whether it is a committed baseline
   or local preview, and verify its conclusion in the owning source repository.
2. **In-tree repo docs and source (authoritative for in-repo detail).** Most
   implementation repos have a root `CLAUDE.md` and per-project
   `project_specs.md`; fall back to `README.md` when no `CLAUDE.md` exists. For
   code-level questions, open the owning repo and verify the relevant source.
   Map of owners:
   - hook contracts, protocols, policies, serialization, providers, config loader,
     executions → `QaaS.Framework` (per-project `project_specs.md`).
   - a specific assertion/generator/probe/processor → the matching `QaaS.Common.*`.
   - runner/mocker behavior → `QaaS.Runner` / `QaaS.Mocker`.
   - release/mirror/schemas → `QaaS.PackageMirror`.
3. **Live docs (authoritative for user-facing config).** `https://docs.qaas.online/`
   (regenerated by `QaaS.Docs.Generator`). Per-hook `overview` / `yamlView` /
   `tableView` pages and `_generated/schemas/*` are ground truth for YAML shapes.
4. **Cross-repo seams** → this plugin's other skills (`qaas-platform-overview`,
   `qaas-graph-workflow`, `add-framework-hook`, `extend-framework-core`,
   `release-and-mirror`).
5. **Not found?** State exactly what is missing and stop. Do not invent.

## Done when

You have named a concrete source (a graph artifact with provenance, repo file
path, or docs URL), verified graph-derived conclusions in source when possible,
or explicitly reported what could not be found.

## Failure modes

- Answering from stale training memory instead of the live source.
- Pointing at this plugin for in-repo detail that belongs in a repo's CLAUDE.md.
- Reporting a graph relationship as current without checking its recorded source
  state or verifying it in the owning repository.
